使用文档

锐智入门

锐智是给普通用户准备的桌面 AI 助手。你不需要懂复杂命令，安装后填入锐擎 APIKey，打开项目文件夹，直接说要做什么。

下载锐智 查看排障

安装登录

1

下载安装

打开首页，按系统选择 Windows 或 macOS。macOS 内测包解压后运行安装脚本，不要直接双击 .app。

2

填入 APIKey

从锐擎控制台复制 APIKey，粘贴到登录页。

3

打开项目

选择需要处理的文件夹，然后直接描述任务。

界面总览

对话

用自然语言描述目标，锐智会读取上下文并继续追问或执行。

差异

修改过的文件会展示变化，方便你确认保留还是继续调整。

命令

测试、构建、搜索日志等命令结果会进入当前线程。

工具

按需连接浏览器、代码托管、文档、日历等外部能力。

第一条任务

任务越具体，结果越稳定。建议一次说清楚目标、范围、约束和完成标准。

“帮我看一下登录失败的原因，先不要改代码。”

“把首页按钮改成加载图标，改完后检查页面有没有明显中文字体问题。”

“阅读这个模块，写一份非技术同事也能看懂的说明。”

常用流程

描述目标 说清楚要解决什么问题。
确认方案 复杂任务先让锐智列计划。
执行修改 让锐智改文件或运行命令。
检查结果 看差异、跑验证、继续调整。

最佳实践

先小后大

不要一次塞太多目标。先让锐智定位问题，再让它修改。

给出边界

明确哪些文件能改、哪些不能改，是否需要兼容旧版本。

要求验证

修改完成后让锐智运行测试、构建或打开页面检查。

保留规则

把团队约定写进项目根目录的 AGENTS.md，让锐智每次都按规则做事。

推荐写法

“目标是……；只改……；不要动……；完成后运行……；最后告诉我改了什么。”

项目与线程

锐智按项目目录理解上下文。每个任务会形成一个线程，线程里保留你的要求、读取过的文件、命令结果和修改记录。

  • 打开文件夹后再提问，锐智能结合项目代码回答。
  • 同一个问题可以在原线程继续追问，不需要重复解释背景。
  • 复杂任务建议拆成小步骤，例如先排查、再修改、最后验证。

代码审查

锐智可以阅读改动、指出风险、解释差异，也可以按你的要求修复问题。提交前建议先让它做一次审查。

  • 检查逻辑 bug、边界条件、测试缺口和潜在回归。
  • 在差异视图里逐个确认修改。
  • 连接代码托管平台后，可以协助查看 PR、评论和 CI 失败原因。

终端命令

锐智可以在项目目录里运行命令，用于搜索文件、执行测试、启动构建或读取日志。涉及修改系统、删除文件、联网等高风险操作时，应先确认命令内容。

  • 常见命令包括测试、构建、类型检查和格式化。
  • 命令结果会进入当前线程，后续分析可以继续引用。
  • 失败信息不要忽略，直接让锐智根据错误继续修。

浏览器验证

需要验证网页时，锐智可以打开本地页面、检查界面、点击按钮、输入内容，并用截图确认结果。

  • 适合检查官网、后台页面、登录流程和前端交互。
  • 可以让锐智先打开本地地址，再根据实际页面调整样式。
  • 企业登录、删除数据、转移权限等高风险操作需要明确确认。

自动化

重复任务可以交给自动化处理，例如定期检查构建、提醒跟进、监控文档或在稍后继续当前线程。

  • 短时间后继续当前对话，适合用提醒。
  • 长期定期执行，适合用计划任务。
  • 自动化任务要写清楚目标、输入和输出，避免产生无用结果。

技能与插件

技能是给锐智补充专门能力的说明书或工具包。插件可以接入浏览器、文档、日历等外部能力。

  • 团队内固定流程可以沉淀成技能，让锐智按统一方式处理。
  • 连接外部服务前，先确认它需要访问哪些数据。
  • 不需要的插件可以关闭，减少误用和噪声。

项目规则

如果项目根目录有 AGENTS.md，锐智会把它当作项目协作规则。适合写团队约定、构建命令、测试方式、目录说明和禁止事项。

# 项目规则
- 与用户沟通使用中文
- 修改前先查看相关文件
- 前端改动后运行 npm run build
- 不要回滚用户已有改动

故障排除

登录失败

重新复制 APIKey，确认没有多余空格，并检查控制台里的 Key 是否仍有效。

下载不可点

安装包还没上传完成时，按钮会保持不可点。稍后刷新页面即可。

命令失败

把错误信息留在当前线程，让锐智继续根据失败原因修复。

页面效果不对

让锐智打开本地页面，按实际截图继续调整，而不是只看代码猜。

macOS 无法打开

当前 macOS 包未公证。请下载测试包并运行“安装锐智.command”或 install.sh；直接双击 .app 可能只显示无法打开。

结果不符合预期

补充约束和验收标准，要求锐智先列计划再修改。
